# Getting help

This is a single-maintainer learning project, so support is best effort and has no service level. Using the right channel gets you the fastest answer.

| You want to | Use |
| --- | --- |
| Understand how something works, or ask whether an approach is sound | [Discussions](https://github.com/RostomOhannessian/full-ci-cd-pipeline/discussions) |
| Report something that is broken, or a documented command that does not work | [Issues](https://github.com/RostomOhannessian/full-ci-cd-pipeline/issues/new/choose), using the bug or documentation form |
| Report a security vulnerability | [Private report](https://github.com/RostomOhannessian/full-ci-cd-pipeline/security/advisories/new), as described in [SECURITY.md](SECURITY.md) |
| Propose a change | An Issue or Discussion first; see [CONTRIBUTING.md](CONTRIBUTING.md) |

## Before you ask

1. Read [the status page](docs/project/STATUS.md). The feature you want may belong to a later phase.
2. Search existing Issues and Discussions.
3. Run `dev doctor` once it exists (Phase 1). Until then, compare your setup with the prerequisites in the tutorial you are following.

## What to include

- What you ran, the exact output, and what you expected.
- The commit or release you are on, the resource profile (`api`, `lite`, `full`, or `ci`), your operating system and CPU architecture,
  and your Docker version with its memory and CPU allocation.
- Never include secrets, tokens, or personal data. Redact before you paste.

## What this project does not offer

- Support for running it in production, or for adapting it to a specific cloud provider.
- Help with the third-party tools themselves. Their own documentation and communities are better placed. Each tool page in the
  [tool reference](docs/reference/tools/index.md) links the authoritative sources.

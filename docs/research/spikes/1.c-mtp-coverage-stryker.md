# Spike 1.c: Microsoft.Testing.Platform, Code Coverage, and the Stryker.NET preview runner

## Question

Do xUnit v3 on Microsoft.Testing.Platform (MTP), `Microsoft.Testing.Extensions.CodeCoverage`, TRX reporting, and the Stryker.NET 5.0.0 `--test-runner mtp` option work together on .NET 10 when MTP is switched on in `global.json`?

## Risk reduced

- [ADR-0018](../../adr/0018-test-stack-and-quality-gates.md), the test stack, which names MTP, the closed-source coverage extension, and the preview Stryker runner as the riskiest parts.
- [ADR-0004](../../adr/0004-licensing-and-dependency-license-policy.md), because the coverage extension is not under an OSI license.
- Requirement `REQ-QUA-006`, mutation testing reports first and gates later (delivered by WP1.0, WP1.6, WP1.7, and WP4.8).

## Time box and method

- **Time box:** one day or less. The spike took well under that.
- **Environment:** Windows x86-64 with .NET SDK 10.0.401 for the test and coverage runs. Stryker ran in the Linux image `mcr.microsoft.com/dotnet/sdk` at digest `sha256:e70cdb7f80b0348f5cb85f19a8f670fca061f033d57eed12fa003d58b0e06317` (SDK 10.0.401, amd64), for the reason given under Results.
- **Packages and tools (checked 2026-10-06):** `xunit.v3` 4.0.1, `Microsoft.Testing.Extensions.CodeCoverage` 18.11.2, `Microsoft.Testing.Extensions.TrxReport` 2.4.1, `dotnet-reportgenerator-globaltool` 5.5.11, and `dotnet-stryker` 5.0.0.
- **Method:** a small library with a `Money` value object and a `Sku` value object, plus an xUnit v3 test project. The tests leave `Subtract` and the precision rule untested on purpose, so the coverage and mutation numbers are not trivially perfect. A `global.json` pins SDK 10.0.401 with `latestPatch` and sets `test.runner` to `Microsoft.Testing.Platform`.

The pass criteria were fixed before the run:

| Criterion | Gate | Result |
| --- | --- | --- |
| `dotnet test` runs the xUnit v3 project through MTP | Gating | Pass |
| Coverage output is produced and parseable by ReportGenerator and a threshold check | Gating | Pass |
| TRX output is produced | Gating | Pass |
| The coverage extension's license is captured for the ADR-0004 license-note rule | Gating | Pass |
| Stryker produces a mutation score | Reporting only | Pass, in a Linux container |

## Results

### Test run, coverage, and TRX

- **MTP opt-in.** With the `global.json` above, `dotnet test --project <test project> --coverage --coverage-output-format cobertura --report-trx` ran 7 tests, all passing, in about 5 seconds. In MTP mode the SDK takes the project through `--project`, not as a bare path argument.
- **Runner packages.** `xunit.v3` 4.0.1 depends on `xunit.v3.mtp-v2` 4.0.1, so it runs on MTP v2. `Microsoft.Testing.Platform` 2.4.1 and the TRX extension 2.4.1 are MIT licensed. `xunit.v3.mtp-v2` is Apache-2.0 (package metadata, checked 2026-10-06).
- **Coverage.** The extension wrote a Cobertura file. Line coverage was 80.4% (37 of 46 lines) and branch coverage was 80.7% (21 of 26). Per class, `Money` was 71.9% by line and `Sku` was 100%.
- **ReportGenerator.** Version 5.5.11 parsed the Cobertura file and produced the same totals in `Summary.txt` and an HTML report. The report-type option is `-reporttypes`, not `-targettypes`.
- **Threshold check.** The `line-rate` and `branch-rate` attributes on the `coverage` element and on each class are enough for a threshold gate without extra tools. WP1.2's `governance` tooling can read them.
- **TRX.** The file is named `<project>_<tfm>_<arch>.trx` and is what `governance test-summary` (WP1.2) will read.
- **Newer coverage extension.** Version 18.12.0 exists (checked 2026-10-06). The plan pins the 18.11.x line, which worked here. WP1.1 decides whether to move.

### Coverage license (ADR-0004)

`Microsoft.Testing.Extensions.CodeCoverage` 18.11.2 ships `License.txt` with the Microsoft Software License Terms for the Microsoft .NET Library. Its package metadata uses `license type="file"`, not an SPDX expression, and the project page describes it as closed source (checked 2026-10-06). It is therefore a tool-only, non-OSI dependency and needs an ADR-backed license note in the tool inventory, as [ADR-0004](../../adr/0004-licensing-and-dependency-license-policy.md) requires. It is a test-time dependency and is not linked into the shipped API.

### Artifacts carry local details

- The Cobertura `filename` attributes contain absolute paths of the machine that ran the tests.
- The TRX records the computer name and the user name.
- The coverage extension's intermediate folder name includes the account and host name.

On a CI runner these are runner details, not personal data. On a developer machine they are workstation details. `TestResults/` is already ignored by Git. Never paste or commit raw coverage or TRX files, and have the CI upload step publish only the files it needs.

### Stryker.NET 5.0.0 and the MTP runner

- **Windows host: blocked by Application Control.** `dotnet stryker` failed at startup with `FileLoadException ... An Application Control policy has blocked this file (0x800711C7)` on `Buildalyzer.dll`. The host runs Smart App Control in enforce mode (`VerifiedAndReputablePolicyState` was 1, read-only), and 45 of the 104 DLLs in the tool package are not Authenticode-signed. This is a host policy, not a Stryker defect, and the spike did not change it.
- **Linux container: works.** The same command in the Linux SDK image ran the MTP runner. Stryker printed its own warning that the Microsoft Test Platform runner is in preview and that results should be verified.
- **Result.** 58 mutants were created: 13 ignored by the block-already-covered filter, 10 with no coverage, 1 compile error, and 34 tested. 26 were killed and 8 survived. The mutation score was 59.09% (killed divided by killed, survived, and no-coverage mutants). A full run took about 19 seconds.
- **Reports.** The JSON reporter wrote schema version 2 and the Markdown reporter wrote a summary. The valid reporter names are `Progress`, `Dots`, `ClearText`, `ClearTextTree`, `Json`, `Html`, `Dashboard`, `RealTimeDashboard`, `Markdown`, `Baseline`, and `Gitlab`.
- **Inconsistency to know about.** The console table's `# survived` column showed 32 for the whole project, while the JSON and Markdown reports show 8 survived. The 24 extra are the skipped mutants (ignored, no coverage, and compile error). The score is the same in all three outputs, so use the JSON report for numbers.
- **Warning to avoid.** Stryker logged that the test project's simulated build failed and retried with a restore, because the sources had not been restored first. Run `dotnet restore` before Stryker.
- **Tool manifest location.** In SDK 10.0.401, `dotnet new tool-manifest` wrote `dotnet-tools.json` in the current folder, not in `.config/`. `dotnet tool restore` accepted it. WP1.1 should create the manifest in `.config/`, which is where the repository map expects it.

## Conclusion

**Answer:** yes, with conditions.

The gating criteria pass. MTP, Microsoft Code Coverage, TRX, and ReportGenerator work together on .NET 10 with the `global.json` opt-in, so ADR-0018's test stack is viable and WP1.1 and WP1.6 are not blocked.

The reporting-only criterion also passes, with a condition: Stryker's MTP runner is preview and cannot start on a Windows host that enforces Smart App Control. That matches the plan, which runs mutation testing nightly on Linux and reports the score without gating it ([plan section 10.4](../../plans/implementation-plan.md)). Windows contributors can run it through Docker or the Dev Container from WP1.4. No plan amendment is needed.

## Decisions and follow-ups

- ADR: [ADR-0018](../../adr/0018-test-stack-and-quality-gates.md) gains a dated evidence note on MTP, coverage, and Stryker. [ADR-0004](../../adr/0004-licensing-and-dependency-license-policy.md) gains a dated note on the coverage extension license. Neither changes status.
- Inventory: the `ms-code-coverage` and `stryker-net` notes in `docs/reference/tools/inventory.yaml` are updated with the findings.
- Plan changes: none.
- For WP1.1: create the tool manifest in `.config/`, run restore before Stryker, decide on coverage 18.12.0, and keep raw coverage and TRX files out of repository files.
- New risks or Issues: none.

## Reproduce

The commands below are what was run, not a tested script.

```text
dotnet test --project Domain.Tests --coverage --coverage-output-format cobertura --report-trx --results-directory TestResults
dotnet reportgenerator "-reports:TestResults/*.cobertura.xml" "-reporttypes:TextSummary" "-targetdir:TestResults/report"
dotnet dotnet-stryker --test-runner mtp --project Domain.csproj --reporter json --reporter markdown
```
